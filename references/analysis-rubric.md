# 分析口径与判断标准

本文件是 `SKILL.md` 的执行细则。SKILL.md 规定做什么，本文件规定**做到什么程度算合格**。

**口径优先级**：本文件与 `references/methodology.md` 冲突时，以本文件为准。方法论解释理由，本文件定义判定。

## 一、信源等级判定

| 等级 | 判定标准 | 对结论的影响 |
| --- | --- | --- |
| 高 high | 一手原文，可访问官方站点或原始文件，发布主体可核实 | 可给出确定性结论 |
| 中 medium | 权威媒体转述原文，能定位到原始发布主体，但无法访问原文全文 | 结论需标注"据转述" |
| 低 low | 仅二手转述、截图、无链接、无法定位原始发布主体 | 结论一律标注"待核实"，只给立即档 |

**红线**：信源等级为低时，第四部分行动清单最多给到"立即"档，不给 3 个月和 12 个月规划。原因是没有可核实的前提，长期规划全是空转。校验器会对这条做强制检查（`confidence.level == "low"` 时 `actions.quarter` 与 `actions.annual` 必须为空）。

### 材料性质判定（meta.material_nature）

先于一切缺口分析执行，用来区分"文本真在做事"还是"只是修辞"。

| 性质 | 判定特征 | 处理 |
| --- | --- | --- |
| problem_oriented 问题导向 | 罚则、截止日、责任主体、量化考核指标至少有一项可在原文指认 | 具备分析基础，进入正常流程，可按证据评 medium/high |
| declarative 价值宣示 | 上述四项全部缺失，只有宏观号召与价值形容词 | 置信度强制压到 low，只给立即档，不做长期规划 |

**判定边界**：
- 看条款不看标题。标题再强硬，正文没有罚则和责任主体，仍按 declarative 处理。
- 有截止日但无责任主体、无罚则的，按 declarative 处理——没人对逾期负责的期限不构成约束。
- 校验器对 `material_nature == "declarative"` 且 `confidence.level` 为 medium/high 的报告直接报错，不需要人工记住这条规则。

## 二、倡导信号的强度分级

四档，对应 JSON 中的枚举值。**判定只看规范性动词，不看标题语气、不看篇幅、不看发布主体级别。**

| 强度 | JSON 值 | 文本特征（规范性动词） | 应对节奏 |
| --- | --- | --- | --- |
| L1 建议 | `L1-suggest` | "鼓励""支持""倡导""可以""探索" | 观望，不投入 |
| L2 引导 | `L2-guide` | "推动""促进""引导""逐步" | 准备，小成本试水 |
| L3 要求 | `L3-require` | "应当""须""需要""不得" | 限期整改，优先处理 |
| L4 强制 | `L4-mandate` | "必须""严禁""禁止""一律""责令""处罚" | 立即合规，最高优先级 |

判断依据必须是原文措辞，不能凭语感。把原文里的规范动词圈出来作为证据，逐条写进 `signals[].verb`。

**同一份材料内强度不同是常态，不要合并成一条。** 强度分布本身就是信息：如果对 A 群体是 L1、对 B 群体是 L4，说明监管压力集中在哪里。

## 三、结构性缺口的六种类型

反向诊断时，缺口必须归入以下六类之一（JSON 枚举值在括号内），不允许"综合来看存在多方面缺口"这种和稀泥表述：

1. **供给不足**（`supply_shortage`）— 需求已经存在，但合格供给方数量不够
2. **成本过高**（`cost_too_high`）— 有解决方案，但价格让目标人群用不起
3. **信息不对称**（`information_asymmetry`）— 一方掌握的信息远多于另一方，形成议价差
4. **信任缺失**（`trust_deficit`）— 交易双方无法低成本验证对方质量
5. **能力不足**（`capability_gap`）— 需求方知道自己要什么，但不会做
6. **制度缺位**（`institutional_void`）— 规则尚未覆盖，存在灰色地带

**用法**：缺口类型直接决定机会类型。

| 缺口 | 对应的机会形态 |
| --- | --- |
| 供给不足 | 进入市场 |
| 成本过高 | 降本方案 |
| 信息不对称 | 中介服务 |
| 信任缺失 | 认证 / 担保 |
| 能力不足 | 培训 / 代做 |
| 制度缺位 | 合规咨询 |

## 四、缺口的时间属性（最容易亏钱的一步）

| 属性 | JSON 值 | 判定标准 | 误判代价 |
| --- | --- | --- | --- |
| 周期性 | `cyclical` | 每隔固定周期重复出现，已有成熟应对方式 | 误当结构性会过度投入产能 |
| 结构性 | `structural` | 由制度、技术、人口等慢变量决定，短期不会消失 | 误当过渡性会错失窗口 |
| 过渡性 | `transitional` | 由某次变更引发的临时空档，变更完成即消失 | **误当结构性是最常见的亏钱方式**——投入建能力，窗口关了 |

**判定三问**：

1. 这个缺口在本次文件发布之前存在吗？如果一直存在，倾向结构性。
2. 有明确的时间终点吗？（如"过渡期至某年某月"）有终点倾向过渡性。
3. 解决它需要的是"补一个动作"还是"建一种能力"？补动作倾向过渡性，建能力倾向结构性。

写不出判定理由，说明这一项还没想清楚，不要填。

## 五、三道门槛

机会成立与否，取决于三道门槛是否全过。**任何一道不过，机会只存在于"帮别人过门槛"这个位置上。**

| 门槛 | JSON 值 | 判定内容 |
| --- | --- | --- |
| 资质门槛 | `qualification` | 是否需要许可证、备案、执业资格、行业准入 |
| 能力门槛 | `capability` | 是否需要特定技能、团队配置、行业经验 |
| 规模门槛 | `scale` | 是否需要最低资金、产能、渠道覆盖 |

三道全过 → 机会可直接吃到。
部分不过 → 机会转化为"服务那些过不了门槛的人"。
全部不过 → 这不是你的机会，是旁观者的机会。

## 六、位置判断

| 角色 | JSON 值 | 判定标准 |
| --- | --- | --- |
| 受益方 | `beneficiary` | 变化直接增加其收入、降低其成本、或扩大其可选范围 |
| 成本承担方 | `cost_bearer` | 变化要求其付出额外时间、金钱、合规成本，且未获得对价 |
| 中介方 | `intermediary` | 变化不影响其本身，但创造了撮合、代办、认证的服务空间 |
| 旁观方 | `bystander` | 变化与其无直接利益关系，观察即可 |

判定依据必须落到用户的行业、角色、资源情况，不能只说"你是受益方"。

## 七、机会—风险矩阵的填写标准

### 合格示例

> **隐藏机会**：新规要求所有面向未成年人的内容产品做适龄提示，但中小团队没有合规人手。
> **判断依据**：原文第九条明确"2026年6月30日前完成整改"，而整改动作需要内容分级能力，中小团队普遍不具备。
> **门槛**：需熟悉内容分级标准；需在截止日前建立可批量处理的流程。

### 不合格示例

> **隐藏机会**：可以做一些相关服务。
> （问题：没说什么服务、给谁做、依据是什么、门槛是什么）

### 每格必填三项

1. **具体是什么**（`content`，≥15 字）：一句话，含对象和动作
2. **判断依据**（`evidence`，≥15 字）：引用原文条款，或写出完整推理链
3. **门槛 / 触发条件**（`barrier`，≥5 字）：吃到它需要什么资源、能力、资质；风险格则写触发条件

## 八、行动清单的颗粒度要求

**总标准：能否被第三方独立验证是否完成。**

| 档位 | 要求 | 反例 |
| --- | --- | --- |
| 立即（本周内） | 今天或本周就能开始；可逆；验证性（做完能得到新信息） | "研究一下这个行业"（不可验证）、"考虑转型"（不可执行） |
| 3 个月内 | 需投入时间或金钱但规模可控；必须写明投入上限与放弃条件 | "加强学习"（无上限）、"看情况调整"（无放弃条件） |
| 12 个月内 | 结构性布局：能力建设、资产积累、关系网络；必须写明里程碑 | "持续学习""保持关注"（无法验收） |

## 九、止损红线的三要素

止损不是"感觉不对就停"，必须三要素齐全，缺一不可：

| 要素 | JSON 字段 | 要求 |
| --- | --- | --- |
| 观测对象 | `metric` | 可量化或可明确判断的指标 / 事件 |
| 阈值 | `threshold` | 具体的数字、日期或状态 |
| 触发动作 | `action` | `stop` 停止 / `pivot` 转向 / `scale` 加码 |

反例："如果效果不好就停止"——效果不好不是可观测对象。
正例："身份核验状态 / 11 月 20 日前仍未通过 / pivot"。

## 十、置信度评级标准

| 评级 | JSON 值 | 条件 |
| --- | --- | --- |
| 高 | `high` | 一手原文可访问 + 逻辑链每步都有原文支撑 + 缺口归类唯一确定 |
| 中 | `medium` | 原文完整但部分推理依赖假设 + 缺口可能归入两类 |
| 低 | `low` | 信源为二手转述 或 原文关键条款缺失 或 用户处境信息不全 |

**置信度为低时，必须在报告标题下方第一行就标注**，不能放在第六部分。因为用户可能只读开头。

同时必须填写：

- `weakest_link`（≥20 字）：最脆弱的推理环节，要具体到"哪一步"
- `falsifier`（≥15 字）：出现什么反证信号就说明本判断失效
- `missing_info`：还缺哪些关键信息能提高确定性

## 十一、常见误判清单

执行时逐条自查，命中任何一条都要修正：

| 误判 | 表现 | 修正方式 |
| --- | --- | --- |
| 把倡导当事实 | "国家要发展 X，所以 X 一定赚钱" | 倡导说明有缺口，不说明缺口能被填上 |
| 把相关当因果 | "上次政策出台后房价涨了" | 列出至少两个替代解释再下结论 |
| 过度外推 | 从一条地方规定推出全国趋势 | 标注适用范围，不外推 |
| 动机指控 | "他们这么做就是为了收割" | 只分析文本的成本分配，不猜测主观动机 |
| 幸存者偏差 | 只看到成功的案例 | 主动找失败样本或反例 |
| 时间尺度错配 | 用长期趋势指导短期决策 | 明确区分"趋势"与"时点" |
| 伪精确 | "预计增长 37.2%" | 无法验证的数字一律改为区间或定性表述 |
| 缺口时间属性误判 | 把过渡性缺口当结构性缺口 | 用第四节的判定三问重检 |

## 十二、禁止输出的表述

校验器会扫描全文，命中即报错或警告。

### ERROR 级（和稀泥表述，让判断失去信息量）

- "综合来看，机遇与挑战并存"
- "机遇与挑战并存"
- "提升核心竞争力"
- "把握机遇"
- "迎接挑战"
- "全面提升"
- "具体情况具体分析"
- "有待进一步观察"

### WARN 级（空话形容词，让表述失去具体性）

- "赋能"
- "全方位"
- "多维度"
- "专业高效"
- "值得关注"
- "值得期待"
- "高度重视"

### 其他禁止项

- "建议持续关注政策动向"（不可执行）
- "这个行业前景广阔"（无法验证）
- "抓住风口"（无操作定义）
- 任何未标注依据的百分比数字
