# signal-decode · 商业信号解码器

把官方通稿、行业政策、公司公告、平台规则里**反复强调的话**，翻译成"它真正在应对什么问题"，再翻译成"你能做什么"。

> 公开信息里最有用的一句话，往往不是它说了什么，而是它**为什么现在说**。

---

## 这是什么

一个可被 AI Agent 直接调用的技能包（Skill），也是一个可独立维护的开源项目。

输入：一份公开信息原文 + 你的处境
输出：一份六段式结构化报告（信号 → 缺口 → 处境 → 矩阵 → 行动 → 置信度），可同时产出**机器可校验的 JSON 版本**。

## 为什么不是"新闻评论"

原始版本（[news-analysis-prompt](https://github.com/youcare7/news-analysis-prompt)）做的是媒体叙事解构 + 政策分析。这个方向有两个问题：

1. **合规**：个人主体在 WorkBuddy 等平台没有"新闻/媒体/资讯/时政"类目，且《互联网新闻信息服务许可证》要求申请方机构类型为机关——个人无法取得。
2. **实用**：解构叙事很爽，但对"我下个月要不要改方向"没有直接回答。

所以本版本做了三件事：把分析对象从"媒体叙事"收窄到"公开信息文本"；把输出从"洞察"改成"可验证动作"；把判断从"价值评价"改成"成本分配描述"。

## 方法论一句话

**强调什么 → 缺什么 → 谁能补 → 你该怎么动。**

跳过第二步（缺什么），整个分析就退化成情绪共鸣。

完整推导见 [`references/methodology.md`](references/methodology.md)。

## 仓库结构

```
signal-decode/
├── SKILL.md                        # 技能定义（Agent 读取入口）
├── README.md                       # 本文件
├── references/                     # 官方认可子目录：AI 执行时会读取的补充知识
│   ├── analysis-rubric.md          # 执行口径：判定标准、合格/不合格示例、常见误判
│   └── methodology.md              # 理论推导：三推论、四步链路、三门槛、时间属性
├── templates/                      # 官方认可子目录：可复用模板
│   ├── report-template.md          # 六段式报告排版规范
│   └── report.schema.json          # 报告 JSON 结构契约（draft-07）
├── examples/                       # 仓库专用，不随技能包上传
│   ├── example-01-policy.json      # 政策类示例（置信度 medium）
│   └── example-02-platform-rule.json # 平台规则类示例（置信度 high）
├── scripts/                        # 官方认可子目录：AI 通过 Bash 执行
│   └── validate_report.py          # 报告校验器（零第三方依赖）
└── .github/workflows/
    └── validate.yml                # CI：提交即校验示例与包体
```

**目录归类的硬约束**：WorkBuddy 官方技能规范只列出 `references/`、`scripts/`、`templates/` 三个子目录。第一版曾把方法论放在 `docs/`、schema 放在 `schema/`，打包校验时被判定为「非官方子目录，可能被忽略或导致解析失败」。现已全部并入 `references/` 与 `templates/`。

校验器放在 `scripts/` 而不是自定义目录，原因有两层：一是官方只认这三个子目录；二是 `scripts/` 会被打进上传包，用户装完之后**自己也能跑自检**——如果把校验器排除在包外，SKILL.md 里"输出 JSON 后必须跑校验"这条指令在用户机器上就是死链。

`examples/` 则确实不进包：它们是仓库的回归测试样本，技能运行时不需要。

## 快速开始

### 1. 当技能用

只把 `SKILL.md`、`references/`、`scripts/`、`templates/` 打成 zip（顶层目录名 `signal-decode`，条目用正斜杠），上传到 WorkBuddy / Claude Code / 任意支持 SKILL.md 的 Agent 平台。

Agent 读到 `SKILL.md` 后会自动按需加载 `references/`、`templates/`，输出 JSON 版本时调用 `scripts/validate_report.py` 自检。

### 2. 校验示例报告

```bash
python scripts/validate_report.py examples/example-01-policy.json
```

通过时输出：

```
结论: 通过 — 0 个错误, 0 个警告
```

退出码 0 = 通过，1 = 不通过。

### 3. 校验你自己写的报告

```bash
python scripts/validate_report.py path/to/your-report.json
```

校验器会检查：

| 检查项 | 说明 |
| --- | --- |
| 必填字段 | meta / signals / gap / position / matrix / actions / confidence |
| 枚举取值 | doc_type、source_grade、material_nature、strength、gap.type、temporality、role、barrier.kind、stop_loss.action |
| 最小长度 | 每个字段都有下限，防止用"看情况"敷衍 |
| 日期真实性 | YYYY-MM-DD 且为真实存在的日期（`2026-13-45` 会被拒） |
| 矩阵完整性 | 四格必须全填，每格含 content / evidence / barrier |
| 三道门槛完整性 | 资质 / 能力 / 规模 必须全部检验，只填一道会被拒 |
| 止损三要素 | 观测对象 + 阈值 + 触发动作 |
| 材料性质门控 | `declarative` 材料置信度只能为 `low` |
| 置信度门控 | level=low 时 quarter 与 annual 必须为空 |
| 反废话黑名单 | 和稀泥表述报 ERROR，空话形容词报 WARN |

**零第三方依赖**：不 import jsonschema、不 import yaml，只用标准库。因为目标运行环境（Agent 沙箱、CI、Windows 内置 Python）经常没有这些包。

## 设计取舍

**为什么要有 JSON schema，而不只是 Markdown 模板？**

Markdown 模板靠自觉，JSON schema 靠机器。人在写"提升核心竞争力"时不会觉得有问题，校验器会直接报错。约束不住输出格式，方法论就落不了地。

**为什么反废话要分 ERROR 和 WARN 两级？**

第一版把所有黑名单都设成 ERROR，结果示例报告里"数据赋能"被误杀——"赋能"在描述技术作用时是正常用法。一刀切会逼着用户删掉合理表述来通过校验，那校验器就变成了敌人。所以拆成：和稀泥表述（让判断失去信息量）报 ERROR，空话形容词（让表述失去具体性）报 WARN。

**为什么置信度 low 时禁止给长期计划？**

信源是二手转述时给出 12 个月布局，等于用猜测指导决策。错误不在于猜，而在于让读者误以为这个猜测有依据。

**为什么校验器每次运行都要打印边界声明？**

因为它一旦只打印"通过"，就会被当成"结论可靠"。校验器检查的是结构、枚举、长度、日期真实性、黑名单用语——它不知道"这个缺口归类对不对"。字段填满不等于分析成立，这条边界必须每次都说出来，而不是写在文档里等你去查。

## 与原始版本的差异

| 维度 | 原始版本 | 本版本 |
| --- | --- | --- |
| 分析对象 | 媒体叙事、政策文本 | 公开信息文本（政策/公告/规则/报告/通稿） |
| 核心框架 | 解构宏大叙事、个体 vs 系统 | 倡导—缺失反向透视、成本分配描述 |
| 输出形态 | 六段式自由文本 | 六段式 + 可机器校验 JSON |
| 判断标准 | 靠作者自觉 | 校验器 + 反废话黑名单 + 置信度门控 |
| 行动建议 | "提升能力、建立 Plan B" | 可被第三方独立验证的动作 + 止损三要素 |
| 合规定位 | 学术研究与批判性训练 | 商业与职场公开信息分析 |

## 已知局限

- 方法论的核心假设是"倡导的存在意味着缺口的存在"，这个假设在**宣传性材料**上会失效——有些倡导纯粹是价值宣示，不对应任何实际缺口。执行时需要人工判断材料性质。
- 缺口六类型是枚举，现实中的缺口经常是复合型。示例里选了主类型，次要类型写在 reasoning 里。
- 三道门槛（资质/能力/规模）的判定需要具体行业知识，技能本身给不了。它只能提醒你去查，不能替你查。
- 校验器只检查形式合格，不检查判断是否正确。一份形式完美但结论错误的报告能通过校验——这是设计上的边界，不是 bug。校验器每次运行都会打印这条声明。

## 下一步可以改的

按性价比排序，不是按工作量：

1. **缺口复合型**。把 `gap.type` 改成 `primary` + `secondary[]`，让"主类型选错"不再成为单点故障。
2. **补齐示例**。现有 2 个示例覆盖政策类与平台规则类，缺企业公告、行业报告、媒体通稿三类。
3. **SKILL.md 分层**。当前 13.8 KB，可以把九步执行法的细节继续下沉到 `references/`，SKILL.md 只留步骤名与判定要点。但要权衡：拆太碎会导致 Agent 漏读 `references/`，反而降低执行质量。
